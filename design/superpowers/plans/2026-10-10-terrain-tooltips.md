# Terrain Tooltips Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hovering a hex shows what its terrain does (movement, combat, line of sight) in the existing hover tooltip.

**Architecture:** A pure module `src/ui/game/terrainTips.ts` turns (state, hex, viewer, art) into a `TerrainTip`
(name, swatch fields, labelled effect lines) from a `Record<TerrainType, …>` table plus the battle variants. A small
component `TerrainTipBlock.tsx` renders it; `GameScreen`'s `HoverTip` shows it for empty and occupied hexes.

**Tech Stack:** TypeScript, React 18, Vitest (`renderToStaticMarkup` for markup tests).

Spec: `design/superpowers/specs/2026-10-10-terrain-tooltips-design.md`.

## Global Constraints

- Work in the worktree `.claude/worktrees/terrain-tips` (branch `terrain-tips` from `origin/main`); never touch the main checkout.
- Wording follows `design/rules-reference.md` §4, §7–§10, §16, §18.6.
- Open ground and off-board hexes get no terrain block.
- `docs/` is build output: only regenerated by `npm run build` at release time.
- Golden fixtures and art hashes must stay unchanged (this is UI text only).
